# v1.0.0 clean install and health check

This page puts together commands that [RELEASE.md](../RELEASE.md) and
[DAILY_USE.md](../DAILY_USE.md) already document. Nothing new is introduced.
Run them on the NAS, or on any host with Docker and the Compose plugin,
`sqlite3`, `sha256sum` and `curl`.

There are two paths:
- **A. Daily use with your providers**, through `flh-daily.sh`. This is the
  recommended path.
- **B. Plain Compose** with the defaults: rule-based analyzer, no provider
  calls.

> **Don't mix A and B on the same instance.** A plain `docker compose up`
> drops the daily settings and switches to `./data/release`.

## 0. Clean checkout at the tag

Clone into a fresh directory. The tag exists only after publication (see
[the v1.0.0 release plan](../plans/v1.0.0-release.md)).

```bash
git clone --branch v1.0.0 --depth 1 https://github.com/WorldVanquisher/french-learning-hub.git ~/flh-v1.0.0
cd ~/flh-v1.0.0
git describe --tags --exact-match        # expect: v1.0.0
docker version --format 'docker {{.Server.Version}}'
docker compose version
```

## A. Clean install for daily use (`flh-daily.sh`)

This follows [DAILY_USE.md](../DAILY_USE.md) §1–2. Each path below is an
example.

```bash
install -d -m 700 ~/flh-daily-data                        # private data dir, outside the repo
install -d -m 700 ~/.config/flh
install -m 600 scripts/daily/daily.env.example ~/.config/flh/daily.env
"${EDITOR:-vi}" ~/.config/flh/daily.env                   # set FLH_DATA_DIR, FLH_UID/GID, providers, OPENAI_MODEL, key in single quotes
bash scripts/daily/flh-daily.sh check                     # prints only non-secret facts; starts nothing
bash scripts/daily/flh-daily.sh up                        # builds the image, starts, waits until healthy
```

For AI suggestions, also set `SUGGESTION_PROVIDER=openai` in the settings file.
It reuses the `OPENAI_*` values.

**Existing data.** First back up the old database with RELEASE.md's
[*Migrate the daily database*](../RELEASE.md#migrate-the-daily-database)
block. Then run:

```bash
bash scripts/daily/flh-daily.sh restore <that backup directory>
```

## B. Clean install with plain Compose (defaults, no provider)

This follows RELEASE.md's [*First start*](../RELEASE.md#first-start).

```bash
umask 077
mkdir -p data/release && chmod 700 data/release
docker compose up -d --build
docker compose ps                                         # wait for "(healthy)"
```

## Health check (run after any install, upgrade, restore or rollback)

Replace `8080` with your `FLH_HOST_PORT`. Every check is read-only.

```bash
PORT=8080
BASE=http://127.0.0.1:$PORT

# 1. Container state and settings summary (path A); path B: docker compose ps
bash scripts/daily/flh-daily.sh status                    # expect "(healthy)"

# 2. Liveness and readiness
curl -fsS "$BASE/healthz"; echo                           # {"status":"ok"}
curl -fsS "$BASE/readyz";  echo                           # {"status":"ready"}

# 3. Which image is running (record it next to the release)
docker inspect --format '{{.Image}}' french-learning-hub-app-1
docker image inspect --format '{{.Id}}' french-learning-hub:local    # must equal the line above

# 4. Schema: v1.0.0 expects 001 … 013, nothing else
sqlite3 -readonly "$FLH_DATA_DIR/app.db" 'SELECT name FROM schema_migrations ORDER BY name;'
sqlite3 -readonly "$FLH_DATA_DIR/app.db" 'PRAGMA integrity_check;'  # exactly: ok

# 5. The served workbench is the v1.0 bundle (has the record stage summary)
for js in $(curl -fsS "$BASE/" | grep -oE '/assets/[^"]+\.js'); do
  curl -fsS "$BASE$js" | grep -q 'Where this record stands' && echo "v1.0 bundle: $js"
done                                                      # expect at least one line

# 6. Provider switches as configured (path A with suggestions on: true)
curl -fsS "$BASE/concept-suggestion-runs" | python3 -c 'import json,sys; print("suggestions enabled:", json.load(sys.stdin).get("enabled"))'
```

Notes:
- **`FLH_DATA_DIR`** in step 4 is the absolute path from your settings file.
  Set it in the shell first, for example `FLH_DATA_DIR=~/flh-daily-data`. For
  path B, use `./data/release`. Reading the database in read-only mode while
  the service runs is safe.
- **Expected `/readyz` failure.** If `/readyz` returns `503 not_ready`, or step
  1 is not healthy, run `bash scripts/daily/flh-daily.sh logs --tail 50`. Logs
  never contain key values.
- **Browser check through the Mac tunnel**
  ([DAILY_USE.md](../DAILY_USE.md) §3). Open the workbench and confirm that
  **Learning Records** loads and that the language selector switches to
  简体中文 and back. This check is manual: the automated equivalent is the
  packaged browser smoke below.

## Disposable acceptance on a clean checkout (optional, isolated)

This acceptance never targets the daily project, its image tag, its port or
its database. It uses a fake provider with a placeholder key, so no call is
billed. The work directory must be absolute, outside the repository and empty.
See
[V1-PACKAGED-BROWSER-SMOKE.md](../validation/V1-PACKAGED-BROWSER-SMOKE.md) for
what it checks.

```bash
WORK=$(mktemp -d)/flh-v1-accept
# the harness never pulls; fetch the pinned fake-provider image once if it is not local:
docker pull "$(grep -oE 'python:3\.12-slim@sha256:[0-9a-f]{64}' scripts/validation/v1_rehearsal/rehearse.sh | head -1)"
# with a local Chrome/Chromium:
bash scripts/validation/v1_rehearsal/browser_check.sh "$WORK"
# on the NAS (no browser installed; needs the pinned local node:22-bookworm-slim image):
bash scripts/validation/v1_rehearsal/browser_check.sh "$WORK" --browser-container
cat "$WORK/summary.txt"                                   # exit 0 = PASS, 1 = FAIL, 2 = refused, 3 = BLOCKED (no browser)
```

Run only one of the two `browser_check.sh` lines per work directory.
