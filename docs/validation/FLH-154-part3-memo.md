## Checkpoint: G5–G7 with examples, counts and the decision contract (item 48)

### G5: `evaluate` and `quality` disagree (items 41–43)

**Trace (41).** On the parsing fixture's 200 frozen rows:

| Rows | Count | Reference units | `quality` | `evaluate` |
|---|---|---|---|---|
| unit reference, valid output | 155 | 177 | in F1 | in F1 |
| unit reference, non-scorable output | 25 | 28 | **left out** of F1 and of "answered empty" | units **missed** (recall), row **"answered empty"** |
| zero reference, valid output | 17 | 0 | abstention | abstention |
| zero reference, non-scorable output | 3 | 0 | against abstention | against abstention |

The two reports agree on precision (1.0) and abstention (0.85). They disagree on
recall (177/177 vs 177/205 = 0.863), unit F1 (1.0 vs 0.927) and "unit references
answered empty" (0 vs 25). The 25 rows are 3 truncated, 3 with leading prose, 2
with trailing prose, 2 code fences, 2 think blocks, 3 with extra keys, 6 invalid,
2 missing and 2 duplicated (`part3-checks.json` → `p41_g5_trace.disagreeing_rows`).

**Categories (42).** Across nine synthetic systems (the oracle, over-abstention,
an unrelated swap, over-split, merge, duplicate, hallucination on zero,
truncation, unsupported extra):

- **False matches: 0 in every system.** The lexical matcher never paired a unit
  with an objective it did not come from.
- **Unmatched units.** Unmatched predicted units and unmatched reference units on
  valid rows are counted identically by both reports. Examples: an unrelated swap
  leaves 155 of each; over-split and duplicate each leave 180 extra predicted units.
- **Zero-unit references never cause G5.** Both reports count an invalid answer
  against abstention and leave it out of F1.
- **G5 comes only from non-scorable rows on unit references.** Truncating every
  output makes the reports differ on recall and on "answered empty", while F1 is
  null in both.

**Smallest fixture (43).** All 1- and 2-row combinations were searched (files in
`FLH-154/fixtures/`):

- **"Answered empty":** one row suffices, a unit reference with an invalid answer
  (`quality` 0, `evaluate` 1).
- **Unit F1:** two rows are needed, one matched unit and one invalid unit row
  (`quality` 1.0, `evaluate` 0.667). With no valid unit, both F1s are null.

This is the expected-failure regression `CrossReportDenominators`.

### What each metric answers (item 44)

| Metric | Question it answers | Denominator | Gate |
|---|---|---|---|
| strict validity | Does the output pass the production parser and the strict schema? | every row | ≥ 0.98 |
| abstention | Does it say nothing when there is nothing to learn? | every zero-unit reference | ≥ 0.90 (frozen, rb) |
| over-abstention | Does it say nothing when there is something? | every unit reference, valid empty answers | ≤ 0.10 |
| paired consistency / abstain-group accuracy | Does the decision survive a change of cues? | challenge groups | ≥ 0.90 / ≥ 0.80 |
| `quality` unit F1 (today) | Of the valid answers, how close are the units to the references? | valid rows only | none (heuristic) |
| `evaluate` unit F1 | How close is the whole run, a failed answer extracting nothing? | every row | none (heuristic) |
| human unit F1 | The same, judged by a person | judged rows | 0.05 lead (`decision.py`) |
| human false-claim / unsupported / bilingual rates | Is a unit true, raised by the learner, the same in both languages? | judged units | none in `decision.py`; draft gates in the experimental report |

The two F1s answer different questions. Each is legitimate, but they share one
name, and the decision reads the valid-rows one. P1 makes `unit_f1` mean "whole
run" in both reports and keeps `unit_f1_valid_rows` for diagnosis.

### G7: exact pass probabilities (items 52–53)

Exact binomial tails with rational arithmetic. "False pass" is the probability
that a system whose true rate is 0.85 passes; "false fail" that one at 0.95 fails.

| Rule (pass when …) | n = 9 | n = 20 | n = 24 | n = 40* | n = 100 | n = 200 |
|---|---|---|---|---|---|---|
| A point ≥ 0.90 (current abstention, consistency) | 9/9; FP 0.232, FF 0.370 | 18/20; FP **0.405**, FF 0.076 | 22/24; FP 0.280, FF 0.116 | 36/40; FP 0.263, FF 0.048 | 90/100; FP 0.099, FF 0.012 | 180/200; FP 0.026, FF 0.001 |
| A2 point ≥ 0.80 (current abstain-group accuracy) | 8/9; FP **0.600**, FF 0.071 | 16/20; FP 0.830 | 20/24; FP 0.713 | — | 80/100; FP 0.934 | — |
| B point ≥ 0.95 | 9/9; FP 0.232, FF 0.370 | 19/20; FP 0.176, FF 0.264 | 23/24; FP 0.106, FF 0.339 | 38/40; FP 0.049, FF 0.323 | 95/100; FP 0.002, FF 0.384 | 190/200; FP 0.000, FF 0.417 |
| C exact 95 % lower bound ≥ 0.80 | impossible | 20/20; FP 0.039, FF 0.642 | 23/24; FP 0.106, FF 0.339 | 37/40; FP 0.130, FF 0.138 | 87/100; FP 0.347, FF 0.0005 | 170/200; FP 0.549 |
| D exact 95 % lower bound ≥ 0.85 | impossible | 20/20; FP 0.039, FF 0.642 | 24/24; FP 0.020, FF 0.708 | 38/40; FP 0.049, FF 0.323 | 92/100; FP 0.028, FF 0.063 | 179/200; FP 0.042, FF 0.0005 |

\* n = 40 pools frozen and rb, which share their 20 learner texts: it is not 40
independent rows. Applying rule A to both frozen and rb, as the gates do, passes a
system at a true 0.85 with probability 0.164 if the parts were independent. They
are not, so the real figure lies between 0.164 and 0.405. Full tables, including
false pass at 0.80: `part3-checks.json` → `p52_g7_exact`.

**Assumptions:**

- every row is an independent trial with one true rate;
- the references are correct;
- the rate does not vary by case type.

None is guaranteed, so the spread is if anything wider. No rule at n ≤ 24 is good
at both errors. A useful rule (D at n ≈ 100: false pass 0.028, false fail 0.063)
needs a larger held-out abstention set: a new slice with its own matrix. The
frozen evaluation and its digests stay as they are.

### Proposed decision contract (item 47, implemented as a draft)

`flh_extraction/experimental_report.py` (`experimental-report`) sits beside
`decision-report` and changes nothing in it.

- **Never a production GO.** Every report carries `production_go: false`, and no
  input sets it. The only positive verdict is `EXPERIMENTAL_PREFERENCE`, meaning
  "study this system next". The other verdicts are `NO_PREFERENCE`, `PENDING` and
  `BLOCKED`.
- **The same exact gates.** It calls `decision.gates` and `decision.reviewed` as
  they are; tests check that its exact criteria are identical.
- **Explicit human evidence per system:**
  - `unit_f1` with `judged_examples` ≥ 100 and `judged_objectives` ≥ 45;
  - `false_claims` {judged_units, false};
  - `unsupported_units` {judged_units, unsupported};
  - `bilingual_mismatch` {judged_units, mismatched}.

  A missing field, or fewer than 100 judged units, is **PENDING, never zero**
  (item 49).
- **Failed reference review blocks.** More than 10 % rejected is **BLOCKED**,
  whatever the systems score (item 50).
- **Unavailable human review** (item 51) is declared per system, or for all, as
  `{"unavailable": {"reason": …}}`.
  - The report records the reason and stays PENDING; no verdict, rate or
    heuristic stands in for it.
  - Exact-gate failures are still reported, because they need no person. A
    system already excluded by an exact gate does not need human evidence. A
    positive preference always does.
- **Exact-margin leads.** The F1 lead is compared at 3 decimals, so an exact
  0.050 lead counts as a lead (F6).
- **Thresholds are DRAFT** values for the owner to confirm (decision 2).
